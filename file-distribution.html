01

业务定义与任务边界

系统 A 为下游消费方，系统 B 为源系统。系统 A 一般不能直接连接其他系统的数据库，因此通过大数据平台采集源系统表，再通过文件交换平台获取平台生成的文件。采集通常每日一次或每交易日一次，具体以调度配置为准。

本阶段 Agent 的目标是查询并判断测试、生产是否具备目标表的采集和文件导出能力，不自动创建、修改或执行任务。对尚未提供的接口，先明确所需证据及判定方式。

02

采集、分层与导出规则

每张表通常对应 STG、ODS、Export 三个任务。STG 从源表取数并覆盖写入 STG 表；ODS 将 STG 表全量数据写入今日 ODS 分区，分区字段通常为 part_init_date；Export 导出今日 ODS 分区的全部字段，分区日期放在最后一个字段。

全量采集读取源表所有数据；增量采集读取源表指定日期的数据，例如行情表交易日期等于本次采集日期。两类采集的 STG 都覆盖写入，ODS 都读取 STG 全量数据。ODS 的覆盖 / 追加、补数及重跑行为需另行确认。

03

调度组织与系统信息

同一源系统的采集通常归入一个 Flow，包含 STG、ODS、Export 三个 Group，各组包含具体表的 Job。以 o32 为例，任务流为 F_o32，三个任务组为 G_o32_stg、G_o32_ods、G_o32_export。任务名通常包含表名，正式规则待真实示例补充。

独立接口可获取源系统全称、缩写、研发负责人、运维负责人和大数据 STG / ODS 库名。Agent 应先定位系统再匹配库、表和任务，不假设两个环境的库名和任务配置相同。

04

文件交换与下载配置

系统 A 通过文件交换平台获取导出文件。平台需维护两份配置：下载用户与 IP 白名单的对应关系，以及下载用户具有的文件授权。核查时应同时确认下游下载用户的请求来源 IP 是否允许，以及该用户是否具有目标文件权限。

下载使用 GET 方法，请求 URL 中包含用户名和文件路径。具体地址、参数名、编码及其他请求要求待示例确认；平台内部校验顺序不在本次说明中预设。文件生成不等于已具备下载条件，导出文件如何接入交换平台也需补充。

05

核查对象与输出要求

对用户指定的源系统表，分别核查测试、生产的 STG、ODS、Export 任务；获取各层表结构，查询 ODS 最新可用分区，并读取 Export 的字段与分区过滤配置。字段对比应包含字段名、类型、顺序及分区列位置，不能只比较字段数量。

输出按环境列出任务位置、匹配依据、结构、分区和导出字段，汇总差异、缺项及未知项，并记录查询来源和时间。同时检查下载用户、来源 IP 白名单、文件授权和 GET URL 中的用户名及路径。接口支持时，再检查最近执行结果和实际文件。配置存在、执行成功、文件就绪、下载授权和下游获取应分别报告。

06

当前未确定的内容

真实表名与 Job 示例；任务、依赖、脚本、表结构和分区查询接口；环境参数；文件命名、路径、格式、编码、分隔符；导出文件接入交换平台的方式；下载配置查询接口、白名单及授权匹配规则、GET URL 格式；交易日历、业务日期、补数及重跑规则；任务执行和实际文件的查询能力。

“今日”需按任务业务日期解释，不直接等同于服务器运行日期。查询失败或接口缺失应标记为“待核查 / 无法判断”，不能据此判定未采集或未分发。完整 Markdown 文档同时保留了核查步骤和证据清单，便于后续继续补充。
