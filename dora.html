执行角色

02 / EXECUTION FLOWS

把“如何生成”和“如何交付”画清楚。

切换两种方式，查看从问题到结果的完整路径。

BATCH MODE

将计算集中在计划时段，先生成文件，再在指定时间推送。

  1. 01

    配置任务

    指定 Agent、问题 / 参数、执行计划、接收用户与推送时间。

    管理员 · 控制台
  2. 02

    定时触发

    例如 02:00 创建本次批次，发起 Agent 运行。

    系统 · 调度执行
  3. 03

    创建 Session

    记录本次运行上下文，绑定任务与批次，开始取数分析。

    DORA · Agent + Skill
  4. 04

    生成交付物

    例如 03:00 完成分析，获取文件并登记到对应 Session。

    HTML / XLSX / DOCX
  5. 05

    等待推送

    交付物已就绪，保留待推送记录，等待 10:00。

    控制台 · 独立交付计划
  6. 06

    到点交付

    校验文件就绪与用户权限，执行推送并记录结果。

    接收用户 · 渠道待定
运行完成 ≠ 推送完成建议将 Session 执行状态与推送状态分别保存；推送失败时重试交付，无需重新进行数据分析。
LIVE MODE

用户通过自然语言提问与追问，Agent 在 Session 中返回结果。

  1. 01

    用户提问

    选择相应 Agent，输入自然语言问题。

    实时入口
  2. 02

    建立 Session

    新任务通常创建新 Session，后续追问可复用该上下文。

    运行上下文
  3. 03

    取数与分析

    获取 BI 数据集或分析报表，调用绑定的 Skill。

    分析 / 归因 / 制图
  4. 04

    返回结果

    直接回复 Markdown，或生成可获取的文件交付物。

    文字 / Artifact
  5. 05

    继续交互

    用户获取文件或继续追问；新一轮分析可产生新交付物。

    追问 → 取数与分析 ↺
保留实时入口，当前以跑批为主算力约束影响运行策略，Agent / Skill / Session 的核心模型保持一致。并发上限与资源配额可后续配置。
03 / TWO INDEPENDENT CLOCKS

凌晨算完，上午送达。

点击时间节点，观察执行状态与推送状态如何分别变化。以下均为流程示意。

示例时区：Asia/Shanghai
Session 执行状态已完成

分析结束，文件交付物已生成并可获取。

/
交付推送状态等待推送

距计划推送尚有 7 小时，不在生成完成时立即发送。

01

文件先就绪，推送再执行

建议只有文件完整可用且达到推送时刻才发送；没有文件或 Session 异常时转入异常处理。

02

未按时完成，也要有明确策略

若 10:00 仍未生成，需配置延迟推送或跳过并告警；不把空文件或上次结果当作本次成功。

03

交付失败，追踪到具体用户

建议记录批次、Artifact、接收用户和发送结果，避免重复推送；渠道失败可单独重试。

落地前，需要确认的三个接口边界

01

DORA 的运行与结果接口

如何列举 Agent、创建 / 查询 Session、获取异常与 Artifact；采用轮询还是完成回调，取决于 DORA 现有能力。

02

文件保留与交付渠道

文件由 DORA 保管还是归集存储；文件 / 链接如何推送、接收用户如何映射、保留多久，均需确认。

03

时区、超时与重试策略

分别约定执行与推送时区、超时阈值、迟到处理、失败重试和重复发送控制。
